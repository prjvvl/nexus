# Deploy

Nexus runs as a single systemd unit, generated by `install.sh` from
`systemd/nexus.service.template` for whatever user runs the installer:

```ini
[Service]
Type=simple
User=<you>
WorkingDirectory=<install dir>
ExecStart=<install dir>/venv/bin/python <install dir>/main.py
Restart=always
RestartSec=5
```

`Restart=always` means systemd itself restarts Nexus if the process dies —
independent of, and a layer below, the reconciler restarting the *services
Nexus manages*.

## Why `sudo` comes up on every deploy

Nexus itself needs no special privileges. But `systemctl enable/restart` and
`apt-get install` do, and if the account running Nexus has no passwordless
`sudo` configured, every deploy needs one interactive command:

```sh
ssh -t <host> "sudo systemctl restart nexus.service"
```

There's no way around this without either granting passwordless sudo for
just that one systemctl command, or running Nexus's own process-management
scripts (not the installer) with a privilege Nexus doesn't otherwise need.
Neither is set up — this stays a manual step on purpose.

## Deploying to a separate machine

If you edit code on one machine and run Nexus on another (how this project
itself works — developed locally, run on a dedicated host), don't hand-copy
files: push the exact committed tree over SSH, byte-for-byte, so the remote
checkout never silently drifts from a renamed/deleted file an ad-hoc sync
would have left behind.

```sh
# 1. Commit locally first
git add -A && git commit -m "..."

# 2. Push the committed tree to the remote host
git archive HEAD | ssh <host> "mkdir -p ~/infra/nexus && tar -x -C ~/infra/nexus"

# 3. If requirements.txt changed
ssh <host> "cd ~/infra/nexus && ./venv/bin/pip install -r requirements.txt"

# 4. If anything under ui/ changed
ssh <host> "cd ~/infra/nexus/ui && npm install && npm run build"

# 5. Restart (interactive sudo, see above)
ssh -t <host> "sudo systemctl restart nexus.service"

# 6. Verify
ssh <host> "systemctl status nexus.service --no-pager"
ssh <host> "journalctl -u nexus.service -n 30 --no-pager"
curl -s http://<host>:8787/api/services
```

Skip steps 3/4 when their respective inputs (`requirements.txt`,
`ui/package.json`, or anything under `ui/src`) didn't change.

For the remote host to actually be a git repo (so this `git archive` flow
works, and so you can diff/verify against it later), set it up once with a
real clone rather than a loose file tree — see [Install](install.md).

## Verifying parity after a deploy

```sh
git ls-files | sort > local_files.txt
ssh <host> "cd ~/infra/nexus && find . -type f -not -path './.git/*' -not -path './venv/*' \
  -not -path './ui/node_modules/*' -not -path './ui/dist/*' -not -name 'manifest.yaml' \
  -not -name 'state.db' -not -path '*/__pycache__/*' -not -name '*.pyc' -not -name '*.tsbuildinfo' \
  | sed 's|^\./||'" | sort > remote_files.txt
diff local_files.txt remote_files.txt
```
